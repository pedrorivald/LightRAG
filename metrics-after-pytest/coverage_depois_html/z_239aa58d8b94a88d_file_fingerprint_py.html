1"""The file half of the file-backed storages' cross-process fence. 

2 

3`NetworkXStorage`, `NanoVectorDBStorage` and `FaissVectorDBStorage` all 

4coordinate through a file plus a ``storage_updated`` flag distributed by 

5``lightrag.kg.shared_storage``. The flag is published with one Manager RPC per 

6process, so it can be lost -- for one process, for several, or for all -- and a 

7process that misses it keeps a stale snapshot and, on its write path, saves 

8that snapshot over the peer's durable rows. 

9 

10This module is the second channel: the file's own ``(st_mtime_ns, st_size)``, 

11compared against what the process recorded when it last loaded or wrote it. 

12Unlike the flag it is *state* rather than a consumable event, so a failed 

13notification cannot disable it. 

14 

15The two channels are OR-ed and both are kept, permanently: their blind spots do 

16not overlap. The flag fails on a transient manager outage, where the commits 

17are far apart in time and the fingerprint sees them; the fingerprint fails when 

18two commits land inside one filesystem timestamp tick with an identical size, 

19which needs a healthy, fast-committing system -- exactly when the flag works. 

20 

21Four rules a caller must not get wrong, each of which has cost a defect: 

22 

23* **Sample BEFORE reading the file, never after.** A fingerprint taken after 

24 the parse can belong to a newer file than the one now in memory, and 

25 recording it would suppress the reload that file needs -- the one way this 

26 fence could *introduce* a lost write. Callers own this ordering; the 

27 functions cannot enforce it. 

28* **Once a call is committed to adopting, it must not observe the file again.** 

29 Divergence, counting and adoption all run on ONE sample, passed in. 

30* **An unreadable ``stat`` is not an absent file.** ``UNREADABLE`` reports "no 

31 change", degrading the fence to the flag alone; failing towards a reload 

32 would install an empty snapshot the next commit then serializes over the 

33 real one. 

34* **A multi-file storage must look completely published.** ``paths`` is given 

35 in PUBLICATION ORDER, marker last; see :func:`publication_complete`. 

36 

37``st_ino`` is deliberately excluded: ``atomic_write`` frees the previous inode 

38and the allocator hands it straight back (measured at 28 reuses in 30 commits), 

39so it discriminates nothing. Single-process mode skips the test entirely. 

40 

41**Full contract: ``docs/design/FileBackedSnapshotContract.md``** -- the 

42``_missed_notification_reloads`` counter contract and the five ways review 

43found it biased, the deferred ``os.utime`` remedy and why it waits on that 

44counter, and the two blind spots that remain by design. 

45"""

77def sample(paths: Sequence[str], *, workspace: str) -> Fingerprint | object: 

78 """Sample the identity of every path, or ``UNREADABLE`` if any stat fails. 

79 

80 All-or-nothing on purpose: a storage whose state spans two files (FAISS's 

81 index + metadata) has to treat a partially readable pair as "cannot tell", 

82 not as a change. 

83 

84 Routed through ``log_without_raising`` because a ``drop`` commit hook 

85 reaches here after the files are already gone, and every step of such a 

86 hook must be unable to report a completed destruction as an error -- a 

87 broken log sink included. 

88 """ 

89 fingerprints: list[tuple[int, int] | None] = [] 

90 for path in paths: 

91 try: 

92 st = os.stat(path) 

93 except FileNotFoundError: 

94 fingerprints.append(None) 

95 except OSError as exc: 

96 log_without_raising( 

97 logger.warning, 

98 f"[{workspace}] Could not stat {path} to check for peer " 

99 "commits; the reload fence falls back to the notification " 

100 f"flag alone: {exc}", 

101 ) 

102 return UNREADABLE 

103 else: 

104 fingerprints.append((st.st_mtime_ns, st.st_size)) 

105 return tuple(fingerprints)

108def adopted(sampled: Fingerprint | object) -> Fingerprint | None: 

109 """The value to record for ``sampled``. 

110 

111 ``UNREADABLE`` becomes ``None``, which differs from any real file: the next 

112 check therefore re-samples and, if the ``stat`` works by then, reloads 

113 once. That is the safe direction for the *reload decision* — the residue 

114 below is what it is not harmless about. 

115 

116 **Accepted residue — one spurious divergence per unreadable adoption.** 

117 ``None`` means "nothing recorded", and every state reads as a change 

118 against it, so a reload whose sample came back ``UNREADABLE`` leaves the 

119 *next* call reporting a divergence even when the file never moved. It is 

120 the same overcount the module docstring's item 1 rejects, arriving by a 

121 different door: there the fingerprint was invalidated deliberately, here 

122 a failed ``stat`` does it. 

123 

124 Bounded and self-healing: the next readable ``stat`` adopts a concrete 

125 state, so it cannot repeat without the ``stat`` failing again, and it 

126 biases the counter *up*, never down — an inflated counter argues for the 

127 ``os.utime`` remedy the module docstring defers, which is the direction 

128 that costs work rather than data. 

129 

130 **Only a storage that can REPLAY may reload on an unreadable sample.** 

131 That is what keeps the residue at one reload. A reload discards whatever 

132 the process has mutated in memory and not yet committed, and the 

133 storages differ in what that costs: 

134 

135 * The vector backends replay: ``index_done_callback`` reloads and then 

136 ``_flush_pending_locked`` re-applies the pending buffers over the 

137 reloaded snapshot. A spurious reload costs them work and nothing else, 

138 so they adopt ``None`` and move on. 

139 * ``NetworkXStorage`` has no redo log, so a reload DISCARDS those 

140 mutations. Between batches that is the intended behaviour; reached 

141 spuriously it can land *mid*-batch, and then the mutations dropped are 

142 simply absent from the commit that follows — which SUCCEEDS, marking 

143 their document PROCESSED. A silent partial loss, neither loud nor 

144 self-healing. Its ``_reload_locked`` therefore refuses to load on an 

145 ``UNREADABLE`` sample at all (it raises, which fails the batch loudly 

146 and retries), so no reload of its graph can reach this function with 

147 one. What still can are its adoptions of its OWN commit or drop 

148 (``_record_fingerprint``), where the in-memory graph already equals the 

149 file — so the redundant reload discards nothing, **provided it happens 

150 before the next mutation**. It does not on its own: ``UNREADABLE`` 

151 reports "no change", so while the ``stat`` keeps failing no divergence 

152 fires and the reload would be deferred to whichever later call first 

153 managed to ``stat`` — mid-batch, dropping what was applied in between. 

154 ``_get_graph`` therefore settles a ``None`` fingerprint before it 

155 serves the graph — through the divergence test when it can sample (any 

156 concrete state is a divergence against ``None``), by refusing when it 

157 cannot. 

158 

159 Recorded as an option, not done: the obvious fix is to keep the previously 

160 recorded fingerprint instead of clearing it (never worse for the reload 

161 decision, since the file only moves forward and an under-recorded state 

162 fails towards a redundant reload). It is entangled, though — each 

163 storage's ``_adopt_fingerprint`` clears ``_counted_peer_fingerprint`` 

164 exactly when this returns a concrete state, so retaining one here would 

165 clear the dedupe marker on an adoption that did not actually observe the 

166 file, and re-counting would return through 

167 :func:`counts_as_a_new_lost_notification`. Both halves have to move 

168 together, with tests for the pair, which is more than a residue this small 

169 justifies today. 

170 """ 

171 return None if sampled is UNREADABLE else sampled # type: ignore[return-value]

174def counts_as_a_new_lost_notification( 

175 sampled: Fingerprint | object, already_counted: Fingerprint | None 

176) -> bool: 

177 """Whether this detection is a NEW lost notification, not a re-detection. 

178 

179 Every storage here keeps a ``_missed_notification_reloads`` counter, and 

180 the module docstring designates those counters as the evidence the 

181 writer-side ``os.utime`` remedy waits on. That only holds if they count 

182 **distinct unannounced states**, and detection alone does not: a reload 

183 that raises leaves the reader's recorded fingerprint untouched, so the 

184 same state is re-detected by every later call. Counted at each detection, 

185 one state inflates the counter without bound -- and a file that stays 

186 unreadable for a while is not exotic, since that is what a sick storage 

187 looks like. 

188 

189 So each storage remembers the state it last counted and passes it here. 

190 A genuinely different state counts again. Two things do not, and both are 

191 by design (see the module docstring): commits inside one timestamp tick 

192 with an identical size, which produce no new state at all, and commits 

193 that batch into a single observation because this process did not look in 

194 between. This function is the wrong place to fix either -- it is handed a 

195 state and can only compare it with the last one. 

196 

197 ``UNREADABLE`` counts nothing: it cannot say WHICH state it would be 

198 counting, so the count could neither be deduplicated nor trusted. The next 

199 call counts it if the ``stat`` works by then -- but ONLY because the 

200 caller feeds this same sample to its reload, so an unreadable one adopts 

201 no fingerprint and leaves the divergence standing. A caller that sampled 

202 here and let its reload sample independently would lose the event for 

203 good: this would skip the count while that sample succeeded and adopted 

204 the peer state. Count and adopt from one observation. 

205 

206 Counting at detection rather than after a successful reload is deliberate: 

207 the window occurred whether or not this process could reload out of it, 

208 and a file that never becomes readable would otherwise erase the evidence 

209 entirely. 

210 """ 

211 if sampled is UNREADABLE: 

212 return False 

213 return sampled != already_counted

216def peer_commit_detected( 

217 paths: Sequence[str], recorded: Fingerprint | None, *, workspace: str 

218) -> bool: 

219 """Whether the files on disk differ from the ones this process recorded. 

220 

221 The fence's authoritative test -- the one a failed notification cannot 

222 disable. ``False`` in single-process mode and on an unreadable ``stat``. 

223 

224 **A multi-file storage must look completely published**, judged by 

225 :func:`publication_complete` from the files themselves. A publication 

226 renames its files one at a time, so there is a window in which they do not 

227 describe one state, and reloading THAT is what corrupts -- FAISS would pair 

228 one generation's ``.index`` with another's ``.meta.json`` and bind one 

229 row's metadata to another's vector. A pair that does not look complete 

230 reports "no change": keeping an older self-consistent snapshot is always 

231 better than adopting an inconsistent one, and it is what this process did 

232 before the fence existed. The writer completes or retries the publication 

233 (its in-memory state plus its redo logs are the authority), and the next 

234 check sees a complete set. 

235 

236 ``recorded is None`` means "nothing recorded, or deliberately 

237 invalidated" and reports a change for any complete state -- it is how a 

238 storage arms the fence after a failure it must reload out of. 

239 """ 

240 if not fence_enabled(): 

241 return False 

242 return divergence_detected( 

243 sample(paths, workspace=workspace), recorded, paths=paths, workspace=workspace 

244 )

247def divergence_detected( 

248 sampled: Fingerprint | object, 

249 recorded: Fingerprint | None, 

250 *, 

251 paths: Sequence[str], 

252 workspace: str, 

253) -> bool: 

254 """:func:`peer_commit_detected`'s decision, from a sample already taken. 

255 

256 For the caller that will DECIDE, COUNT and ADOPT within one call: all 

257 three must come from **one observation**. Taking a fresh ``stat`` for the 

258 decision lets it fail while the caller's sample succeeded, and then the 

259 count is skipped while the reload adopts that good sample -- erasing the 

260 divergence that would have let a later call count the event. The 

261 one-observation rule in :func:`counts_as_a_new_lost_notification` covers 

262 counting and adoption; this covers the third participant. 

263 

264 A caller with nothing else to do with the sample should use 

265 :func:`peer_commit_detected`, which takes one for itself. 

266 """ 

267 if not fence_enabled(): 

268 return False 

269 if sampled is UNREADABLE: 

270 return False 

271 if sampled == recorded: 

272 return False 

273 if len(paths) > 1 and not publication_complete(sampled): 

274 log_without_raising( 

275 logger.warning, 

276 f"[{workspace}] The storage files ({', '.join(paths)}) do not look " 

277 "completely published — the commit marker is older than the files " 

278 "it commits, or the set is partial. Treating this as an " 

279 "interrupted publication, not a peer commit, and keeping the " 

280 "snapshot this process already holds; the writer's retry " 

281 "completes the set.", 

282 ) 

283 return False 

284 return True

287def publication_complete(sampled: Fingerprint) -> bool: 

288 """Whether a multi-file sample looks like one completed publication. 

289 

290 **The last path is the commit marker.** A storage whose state spans 

291 several files publishes them in a fixed order and renames the marker 

292 LAST, so a completed publication leaves the marker STRICTLY newer than 

293 every file it commits, and an interrupted one leaves some file at or 

294 after the marker. That test is what makes completeness judgeable from the 

295 files alone -- by any process, at any generation of staleness. 

296 

297 **Strictly**, not "no older", and that is the whole guard against coarse 

298 filesystem timestamps. A torn set can land its next file inside the same 

299 timestamp tick as the previous publication's marker, making the two 

300 mtimes equal; ``<=`` would call that complete and hand back a set whose 

301 files describe different generations. ``<`` refuses it. 

302 

303 The cost is in the safe direction: a COMPLETE publication whose writes all 

304 land inside one tick is also refused, so its commit goes unnoticed by this 

305 channel. That is a missed reload, not a torn one -- the process keeps a 

306 self-consistent snapshot, the flag channel carries that commit (a 

307 same-tick publication means a healthy, fast-committing writer, which is 

308 exactly when the flag works), and the next publication that spans a tick 

309 is seen. Compare the mirror residue on the change-detection side, where 

310 the same tick collision also costs a detection rather than correctness. 

311 

312 Comparing per-file changes against what a reader last recorded cannot do 

313 that: a reader several generations behind sees every file changed even 

314 when the newest publication is half-landed, so it would take a torn pair 

315 for a commit. Ordering is a property of the files; a recorded fingerprint 

316 is a property of one reader. 

317 

318 Everything absent is complete (the post-``drop`` state, which peers must 

319 be able to converge on). A present marker with any file missing is not. 

320 

321 **This test is timestamp-based because the formats give it nothing else.** 

322 The deferred remedy, recorded so it is not rediscovered: put an explicit 

323 generation counter in the metadata each file carries (FAISS's 

324 ``meta.json``), or publish the set atomically -- stage a whole generation 

325 in a directory and rename that directory into place -- and completeness 

326 becomes a comparison of equal generation numbers, independent of the 

327 filesystem clock and of the strictness argument above. It is not done here 

328 because it is a storage-format change, and these multi-file backends are 

329 development and test storage today. It is the right answer if they ever 

330 become production storage. 

331 """ 

332 *committed, marker = sampled 

333 if marker is None: 

334 return all(entry is None for entry in committed) 

335 if any(entry is None for entry in committed): 335 ↛ 336line 335 didn't jump to line 336 because the condition on line 335 was never true

336 return False 

337 marker_mtime = marker[0] 

338 return all(entry[0] < marker_mtime for entry in committed)
