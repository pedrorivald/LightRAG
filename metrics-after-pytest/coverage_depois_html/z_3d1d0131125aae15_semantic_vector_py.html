1"""Semantic vector chunking — the ``"V"`` strategy. 

2 

3Wraps LangChain's :class:`SemanticChunker` (from ``langchain-experimental``) 

4which splits text by sentence embeddings: it first segments the input into 

5sentences, embeds each sentence (in adjacent windows of ``buffer_size``), 

6and finds breakpoints where the cosine distance between consecutive 

7windows crosses a threshold derived from the chosen distribution 

8(``percentile`` / ``standard_deviation`` / ``interquartile`` / 

9``gradient``). 

10 

11The chunker exposed here is ``async`` because LightRAG's 

12:class:`EmbeddingFunc` is async. Internally we call SemanticChunker 

13synchronously inside :func:`asyncio.to_thread` and bridge the embedding 

14calls back to the main event loop via 

15:func:`asyncio.run_coroutine_threadsafe`. 

16 

17Caveats: 

18 - SemanticChunker does NOT enforce a maximum chunk size; the caller's 

19 ``chunk_token_size`` is *advisory* here. Oversized chunks will be 

20 hard-split before embedding by 

21 :func:`lightrag.utils.enforce_chunk_token_limit_before_embedding`. 

22 That function only covers the chunks this module *emits*; the 

23 sentence-window embeddings V performs while chunking are bounded 

24 separately, see below. 

25 - When ``embedding_func`` is ``None`` we log a warning and fall back to 

26 :func:`lightrag.chunker.chunking_by_recursive_character` — V's only 

27 differentiator is embeddings, and R is the closest structural-only 

28 alternative. 

29 

30Embedding request bounding: 

31 Upstream ``SemanticChunker`` embeds the *whole document* in a single 

32 ``embed_documents`` call — one item per sentence window, so the request 

33 carries ``N = sentence count`` items and roughly 

34 ``(2 * buffer_size + 1) x document`` tokens. No provider binding in 

35 ``lightrag/llm`` slices that list, so a large enough document breaks 

36 the service's per-request limits. :class:`_AsyncEmbeddingFuncAdapter` 

37 therefore batches by item count and truncates each window. What is 

38 guaranteed, per ``chunking_by_semantic_vector`` call: 

39 

40 * every provider request carries at most ``embedding_batch_num`` 

41 items (``<= 0`` deliberately disables batching and gives up the 

42 bound entirely); 

43 * at most ``embedding_max_async`` requests from this one adapter are 

44 in flight at a time — cross-instance concurrency is the priority 

45 wrapper's job, not this pool's; 

46 * once one batch's failure is observed, no further batch is started. 

47 

48 Per-item token counts are **best effort only**: the truncation uses 

49 LightRAG's general-purpose tokenizer, which need not match the 

50 embedding model's, and providers may rewrite the input afterwards 

51 (``openai_embed`` prepends ``document_prefix`` before its own 

52 truncation). ``batch_size * budget`` is a logical bound under the 

53 adapter's tokenizer, never a promise about what the service receives. 

54 Truncation cannot lose chunk content: the emitted chunks are original 

55 source spans, so only the boundary distance computation degrades. 

56"""

97class _AsyncEmbeddingFuncAdapter(Embeddings): 

98 """Bridge a LightRAG :class:`EmbeddingFunc` (async) to LangChain's 

99 sync :class:`Embeddings` interface used by ``SemanticChunker``. 

100 

101 The adapter must be constructed inside the running event loop so it 

102 can capture the loop reference; the blocking ``embed_documents`` / 

103 ``embed_query`` calls are then made from a worker thread (via 

104 :func:`asyncio.to_thread` in the public chunker) and bounce back to 

105 the captured loop with :func:`asyncio.run_coroutine_threadsafe`. 

106 

107 Every call truncates each text to ``max_token_size`` and splits the 

108 list into ``batch_size``-item provider requests, running at most 

109 ``max_concurrency`` of them at a time. See the module docstring for 

110 exactly what that does and does not guarantee. 

111 

112 .. warning:: 

113 Never invoke this adapter from inside the chunking executor. That 

114 pool has a single worker (see ``run_in_chunking_executor``), and a 

115 blocking ``future.result()`` there would occupy it — while 

116 ``chunking_by_semantic_vector``'s own fallback path submits to the 

117 same pool. Today the adapter only runs on the *default* executor 

118 via ``asyncio.to_thread``; ``_size_and_resplit`` is the part that 

119 runs in the chunking pool, and it never touches the adapter. 

120 Moving an embedding bounce into it would deadlock. 

121 

122 Related, unchanged by the batching: an ``embedding_func`` that 

123 wraps a *synchronous* SDK in ``asyncio.to_thread`` competes with 

124 V's own blocking thread for default-executor workers (one thread 

125 per document either way). 

126 """

224 async def _embed_all(self, batches: list[list[str]], context: str) -> list[Any]: 

225 """Run ``batches`` through ``embedding_func``, at most 

226 ``max_concurrency`` at a time, results in batch order. 

227 

228 A bounded worker pool rather than ``asyncio.gather`` over every 

229 batch: ``gather`` without ``return_exceptions`` raises the first 

230 error to its awaiter but does NOT cancel the remaining awaitables, 

231 so one 429 would leave thousands of batches hammering the provider 

232 after the document had already failed. It also materialises one 

233 Task per batch up front. ``asyncio.TaskGroup`` would do, but the 

234 project floor is Python 3.10. 

235 

236 The pool also bounds how many queue slots V occupies in 

237 ``priority_limit_async_func_call``: that wrapper enqueues at CALL 

238 time, so keeping calls in flight bounded keeps queued tasks 

239 bounded. It is NOT here to limit execution concurrency — the 

240 wrapper already caps that at ``embedding_func_max_async``; it is 

241 here so V cannot park thousands of coroutines behind the (1000 

242 slot, blocking-on-full) queue and add minutes of latency to 

243 queries. 

244 """ 

245 results: list[Any] = [None] * len(batches) 

246 cursor = iter(range(len(batches))) 

247 # Single-threaded event loop: next() on the shared iterator cannot 

248 # interleave, so no lock is needed. 

249 stopped = asyncio.Event() 

250 

251 async def _worker() -> None: 

252 for i in cursor: 

253 # Checked before every batch, and set in the except below 

254 # rather than relying on the outer gather's cancellation: 

255 # between one worker's failure and that error reaching the 

256 # awaiter, the other workers would otherwise have pulled 

257 # and dispatched fresh batches, breaking the "no new batch 

258 # after a failure" guarantee. CancelledError is a 

259 # BaseException too, so an outer cancel also stops intake. 

260 if stopped.is_set(): 

261 return 

262 try: 

263 results[i] = await self._embedding_func(batches[i], context=context) 

264 except BaseException: 

265 stopped.set() 

266 raise 

267 

268 tasks = [ 

269 asyncio.create_task(_worker()) 

270 for _ in range(min(self._max_concurrency, len(batches))) 

271 ] 

272 try: 

273 await asyncio.gather(*tasks) 

274 except BaseException: 

275 for task in tasks: 

276 task.cancel() 

277 await asyncio.gather(*tasks, return_exceptions=True) 

278 raise 

279 return results

281 def cancel_inflight(self) -> None: 

282 """Refuse all further work, and cancel the in-flight bounced call. 

283 

284 Called from the event loop when the outer chunking task is 

285 cancelled. Cancelling the bridging future wakes the blocked worker 

286 thread and — through ``_chain_future``'s cancellation callback — 

287 cancels the loop-side task, and with it the worker pool. 

288 

289 The sticky flag is the other half, and it is not optional. 

290 ``asyncio.to_thread`` can still be QUEUED when the cancellation 

291 arrives (or running the grouping before it first reaches this 

292 adapter), in which case there is no future to cancel yet. Without 

293 the flag that cancellation would simply be dropped, and the worker 

294 thread would go on to publish a fresh future and dispatch every 

295 batch of an already-cancelled document. 

296 """ 

297 with self._cancel_lock: 

298 self._cancelled = True 

299 future = self._inflight 

300 if future is not None: 

301 future.cancel()
