1"""Multimodal analysis prompts for LightRAG. 

2 

3These templates are consumed by ``LightRAG.analyze_multimodal`` to produce 

4modality-specific analysis JSON written into each sidecar item's 

5``llm_analyze_result``. 

6 

7Each template accepts the same variable set so the caller can format them 

8uniformly: 

9 

10- ``language`` : target language for ``name`` / ``description`` outputs. 

11- ``content`` : modality body (table JSON/HTML, equation LaTeX, etc.). 

12 Images pass an empty string and rely on ``image_inputs``. 

13- ``captions`` : caption text or ``"n/a"``. 

14- ``footnotes`` : joined footnotes string or ``"n/a"``. 

15- ``leading`` : surrounding leading context or ``"n/a"``. 

16- ``trailing`` : surrounding trailing context or ``"n/a"``. 

17- ``item_id`` : sidecar item identifier (for diagnostics, not required by 

18 every template). 

19- ``file_path`` : source document path (diagnostics only). 

20 

21The output schema differs by modality: 

22 

23- Image : ``{"name": str, "type": str, "description": str}`` 

24- Table : ``{"name": str, "description": str}`` 

25- Equation : ``{"name": str, "equation": str, "description": str}`` 

26 

27Image ``type`` is restricted to :data:`IMAGE_TYPE_ENUM`; values outside the 

28enum are folded into :data:`IMAGE_TYPE_FALLBACK` by the caller. 

29""" 

30

52_TABLE_FORMAT_LABELS: dict[str, str] = { 

53 "html": ( 

54 "HTML format — a <table> fragment where merged cells use " 

55 "rowspan/colspan and the header (if any) is inside <thead>" 

56 ), 

57 "json": ( 

58 "JSON format — a 2-D array where each inner array is one table row " 

59 "(rows[i][j] is the cell at row i, column j); the first row(s) may be " 

60 "the header" 

61 ),

65def table_content_format_label(fmt: str) -> str: 

66 """Human-readable format declaration for the ``table_analysis`` prompt. 

67 

68 Maps the sidecar table item's ``format`` (``"html"`` / ``"json"``) to a 

69 short clause describing how to read the body. Raises :class:`ValueError` on 

70 any other value — a table item written by the sidecar writer ALWAYS carries 

71 a valid format, so a missing/unknown one means a corrupt or incompatible 

72 sidecar and must fail loudly rather than be guessed. 

73 """ 

74 key = (fmt or "").strip().lower() 

75 try: 

76 return _TABLE_FORMAT_LABELS[key] 

77 except KeyError: 

78 raise ValueError( 

79 f"unknown table format {fmt!r}; expected 'html' or 'json'" 

80 ) from None

253] = """You are an expert analyzer of mathematical and chemical equations. The input is a TEXT-form equation written in LaTeX or Markdown. Analyze it and return a single JSON object describing its meaning and role. 

254 

255================ INSTRUCTIONS ================ 

256 

2571. CONTENT RECOGNITION 

258 Read the equation carefully and identify: 

259 - The type of expression: definition, identity, equation to solve, inequality, differential / integral equation, recurrence, chemical reaction, balance equation, etc. 

260 - The mathematical or chemical meaning of the expression as a whole. 

261 - The variables, constants, operators, and functions that appear, and what each likely denotes given the surrounding context. 

262 - The application domain (e.g. classical mechanics, probability, thermodynamics, organic chemistry, machine learning loss function) inferred from context. 

263 - Any physical, statistical, or theoretical significance. 

264 - Whether the expression matches a well-known named formula (e.g. Bayes' theorem, Schrödinger equation, softmax, Michaelis–Menten). Name it explicitly when you are confident; do NOT guess. 

265 

2662. USE OF ADDITIONAL CONTEXT 

267 The Additional Context section provides surrounding information to help you understand the equation's role in its source document: 

268 - Captions : the equation's caption or label ("n/a" = none) 

269 - Footnotes : footnote attached to the equation ("n/a" = none) 

270 - Leading Text : text appearing immediately BEFORE the equation ("n/a" = none) 

271 - Trailing Text : text appearing immediately AFTER the equation ("n/a" = none) 

272 

273 Rules: 

274 - Use context to determine variable meanings, units, and the domain of discussion. 

275 - THE EQUATION ITSELF TAKES PRIORITY over context if they conflict; note the discrepancy if material. 

276 - Only mention a relationship between the equation and Leading/Trailing Text if it is clearly supported. If uncertain, omit it. 

277 - Captions, footnotes, leading text and trailing text may only be used for disambiguation purposes and must not be used to infer or fabricate content not present in EQUATION BODY. 

278 - NEVER invent variables, terms, or interpretations that are not justified by either the equation or the context. 

279 

2803. NAMING (`name`) 

281 - Produce a concise, distinctive name (3–8 words, snake_case preferred). 

282 - It should convey what the equation IS or DOES, not just "equation". 

283 - Good examples: 

284 `bayes_theorem_posterior` 

285 `softmax_cross_entropy_loss` 

286 `ideal_gas_law` 

287 `michaelis_menten_rate` 

288 `combustion_of_methane` 

289 `quadratic_formula_roots` 

290 - Bad examples: 

291 `equation`, `formula`, `math`, `the_equation`, `eq_1` 

292 

2934. NORMALIZED EQUATION (`equation`) 

294 - Output the math-mode BODY ONLY. Do NOT wrap in any delimiter or environment: no `$...$`, no `$$...$$`, no `\\(...\\)`, no `\\[...\\]`, no `\\begin{{equation}}...\\end{{equation}}`. 

295 - Strip those outer wrappers if present in the input. 

296 - KEEP semantic inner environments such as `aligned`, `cases`, `pmatrix`, `bmatrix`, `array`, `split` — they are part of the equation's structure, not delimiters. 

297 - If the input uses `\\begin{{align}}` or `\\begin{{align*}}`, convert to `\\begin{{aligned}}`. 

298 - Strip equation numbering (`\\tag{{...}}`, automatic numbers from `align`/`equation`). 

299 - Preserve all symbols, subscripts, superscripts, and operators faithfully. Do NOT simplify or rename variables. 

300 - Convert Markdown / plain-text / Unicode math to standard LaTeX (`x^2` → `x^{{2}}`, `sqrt(a)` → `\\sqrt{{a}}`, `≤` → `\\leq`, `α` → `\\alpha`). 

301 - For chemical equations, use `mhchem`: `\\ce{{2H2 + O2 -> 2H2O}}`. 

302 - If multiple independent equations appear together, join them with `\\\\` inside a single `\\begin{{aligned}}...\\end{{aligned}}` and note the grouping in `description`. 

303 

3045. DESCRIPTION (`description`, ≤ 300 words, natural prose — not bullets) 

305 Cover the following where applicable: 

306 - What the equation expresses and what problem it addresses. 

307 - Its role in the surrounding text (e.g. defines a quantity, states a constraint, derives a result, models a phenomenon). 

308 - The named formula it corresponds to, if any, and where it is commonly used. 

309 - Briefly clarify only those symbols whose meaning is non-obvious or domain-specific, OR whose meaning is fixed by the Leading/Trailing Text. Do NOT enumerate every symbol mechanically. 

310 - Use specific proper nouns (variable names, entity names) instead of pronouns. 

311 - If the equation clearly illustrates or supports the surrounding context(leading or trailing text), briefly note that relationship at the end. Otherwise omit. 

312 

3136. OUTPUT RULES 

314 - Return ONE valid JSON object only. 

315 - No surrounding markdown, no code fences, no preamble, no explanation. 

316 - All string values must be properly escaped JSON strings (escape `"` as `\\"`, escape backslashes as `\\\\`, newlines as `\\n`). 

317 - LaTeX backslashes inside the `equation` string must be double-escaped (e.g. `\\frac{{a}}{{b}}` is written as `"\\\\frac{{a}}{{b}}"` in the JSON). 

318 - If the input uses `\\begin{{align}}` or `\\begin{{align*}}`, convert to `\\begin{{aligned}}` in the output (since the outer display wrapper is stripped). 

319 - The output values for the JSON fields `name` and `description` must be written in `{language}`.

323{content}
