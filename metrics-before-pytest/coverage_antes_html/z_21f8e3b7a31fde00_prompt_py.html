36# Wrapper block for the optional per-chunk section breadcrumb. The 

37# `---Section Context---` heading lives ONLY here so the extraction code never 

38# hardcodes the marker; it produces the breadcrumb string and decides whether 

39# to inject this block at all. When a chunk has no heading the block is omitted 

40# entirely and the user prompt stays byte-identical to the no-context form. 

41# 

42# Security: the breadcrumb is document-controlled text and is defended on two 

43# levels. (1) Structural: it is collapsed to a single line upstream 

44# (``_clean_heading_text``) and placed *after* a label on the same line, so it 

45# can never sit at the start of a line — structural prompt markers (`---X---` 

46# sections, ``` fences) are line-start constructs, so a heading such as 

47# `---Output---` renders inline as inert data and cannot forge a prompt section 

48# outside the input fence. (2) Behavioral: the inline label marks it as 

49# untrusted metadata and tells the model not to follow instructions inside it, 

50# right next to the data where the cue is most effective.

658def load_user_prompt_prefix_source() -> str: 

659 """Resolve the operator's global ``user_prompt`` prefix from the environment. 

660 

661 ``USER_PROMPT_PREFIX_FILE`` names a ``.md``/``.txt`` file inside 

662 ``PROMPT_DIR/user_prompt`` and takes precedence over the inline 

663 ``USER_PROMPT_PREFIX``; the file form exists because a ``.env`` value must 

664 stay on one physical line and cannot carry a literal ``${...}``.

666 The value is returned verbatim — no stripping, no separator appended. The 

667 operator owns the formatting and ends it with their own newlines (a file 

668 naturally ends with one). See :func:`lightrag.utils.resolve_user_prompt`. 

669 

670 Never raises: this runs inside ``LightRAG()`` via a dataclass 

671 ``default_factory``, where an exception surfaces far from its cause. Any 

672 failure is logged and degrades to no prefix. 

673 """

677 if not file_name:

679 # since two env vars can supply this value and either may be empty. 

680 # Source and length only -- the content is multi-line operator policy. 

681 if inline: 

682 logger.info( 

683 "User prompt prefix loaded from USER_PROMPT_PREFIX (%d chars)", 

684 len(inline),

686 return inline

688 if inline:

691 "using the file '%s' and ignoring the inline value.", 

692 file_name, 

693 ) 

694 

695 try: 

696 prefix_path = resolve_user_prompt_prefix_path(file_name) 

697 except (ValueError, OSError, RuntimeError) as exc: 

698 # ValueError is the sandbox's own rejection. The other two come from 

699 # resolving PROMPT_DIR itself: Path.expanduser() raises RuntimeError when 

700 # a home directory cannot be determined, and Path.resolve() raises 

701 # RuntimeError (<=3.12) or OSError on a symlink loop. Letting either 

702 # escape would abort every LightRAG() construction, since this runs as a 

703 # dataclass default_factory -- the exact opposite of the degrade-and-log 

704 # contract documented above.

708 exc,

710 return ""

712 try:

714 except (OSError, UnicodeDecodeError) as exc:

721 

722 # Log the resolved path, not the configured name: it is what an operator 

723 # checks to confirm which file actually won. An empty file logs too -- 

724 # "0 chars" is itself the answer to "why is my prefix not applied?". 

725 logger.info(
