1"""Shared template for native (local, in-process) parser engines. 

2 

3``NativeParserBase.parse`` fixes the common local-parse flow once: 

4 

5 resolve + validate source → compute parsed_dir/asset_dir 

6 → pre-clean (rmtree parsed_dir + mkdir + mkdir asset_dir, with rollback) 

7 → extract() in a thread → build_ir() → write_sidecar(clean_parsed_dir=False) 

8 → persist full_docs (lightrag) → archive source 

9 

10Subclasses implement ``extract`` (sync, runs in a thread) and ``build_ir``.

313 # Whether _extract_sync got as far as replacing parsed_dir. Written in 

314 # the executor thread, read here after the await. It exists because the 

315 # two failure modes need opposite handling: once the directory is being 

316 # replaced a failure must roll it back, but a refusal that happens 

317 # BEFORE that must leave the previous attempt's sidecar alone. 

318 # 

319 # For normal completion the future's completion is the happens-before 

320 # edge, but a CANCELLED future completes while the worker thread is 

321 # still running — so the checkpoint's {read events, set flag} and the 

322 # coroutine's {set cancel_event, read flag} race. cleanup_lock makes 

323 # each of those a critical section: the coroutine either sees 

324 # cleanup_started before the worker commits to the rmtree (and rolls 

325 # back) or the worker sees the cancel event at the checkpoint (and 

326 # never starts). Both sections are pure in-memory work, so holding the 

327 # lock never blocks on I/O. 

328 cleanup_started = False 

329 cleanup_lock = threading.Lock()

331 def _extract_sync(): 

332 nonlocal cleanup_started 

333 # Read-level validation runs here, not in parse(): it opens the 

334 # source, and on the event loop that cost is paid by every other 

335 # request. 

336 self.validate_source_blocking(source, ctx.file_path) 

337 # Cancellation checkpoint, and the last moment one is useful. 

338 # Cancelling run_in_executor cancels only the future — THIS thread 

339 # keeps running, and everything below destroys parsed_dir and 

340 # rebuilds it. Ordinary extraction polls nothing, so without this 

341 # a cancel arriving during validation lets an abandoned worker 

342 # delete a complete sidecar from an earlier parse and leave a 

343 # partial one behind, after the coroutine has already returned. 

344 # The source is gone from INPUT_DIR by then, so that is not 

345 # recoverable. 

346 # 

347 # Raise ParsePipelineCancelled, NOT asyncio.CancelledError: 

348 # the pipeline-level cancel (_watch_pipeline_cancellation) only 

349 # SETS ctx.pipeline_cancel_event, it never cancels the worker task, 

350 # so a CancelledError raised here would be set on a live, un- 

351 # cancelled future and re-raised into _parse_worker as a 

352 # BaseException that matches neither of its except clauses — the 

353 # doc would strand in PARSING and, if every worker died this way, 

354 # wedge the batch on q.join() with busy=True. ParsePipelineCancelled 

355 # is the repo-wide "blocking parse wait was cancelled" signal that 

356 # _parse_worker catches to mark the doc cancelled. In the task- 

357 # cancel case the future is already cancelled, so awaiting it raises 

358 # CancelledError regardless of what the worker raised — one uniform 

359 # raise covers both. 

360 # 

361 # The rag-level shutdown event is checked here too, and raises the 

362 # distinct ParseShutdown. _shutdown_parser_executor() sets it 

363 # and then calls executor.shutdown(wait=False), i.e. it does NOT 

364 # wait for a running extract — its contract is that in-flight work 

365 # exits via the event. Without this branch a worker still inside 

366 # validate_source_blocking when finalize_storages() runs would walk 

367 # on to rmtree parsed_dir and extract into storages being torn down. 

368 # Shutdown stays a generic parse failure for audit (the parse worker 

369 # catches only PipelineCancelledException / ParsePipelineCancelled 

370 # as "cancelled"), which is the documented intent. 

371 pipeline_cancelled = ctx.pipeline_cancel_event
